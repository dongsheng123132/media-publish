# 发布矩阵 · 作战手册（2026-11-17）

> 这份手册回答三个问题：**去哪些地方注册**、**按什么顺序发**、**哪些坑会让你白忙一天**。
> 数据在 [`platforms.json`](platforms.json)（35 家，逐条带核实日期与证据链接），
> 作战台用 `node build-matrix.mjs platforms.json --product products/<产品>.json` 生成。

---

## 0. 一句话结论

**发布板不是流量来源，是证据链。**
它给你三样东西：① 能被 AI 与 Google 读到的第三方页面（语料 + 外链）② 首批愿意留一句真评论的人
③ 一条「这个产品存在且有人在用」的公开记录。**安装量不从这里来**，从 App Store 搜索、短视频、小语种榜来。

所以排序永远是：**先让自己「可被搜到」→ 再一次性铺满目录 → 最后才谈榜单名次。**

## 1. 为什么 AI 会推荐某几个产品，不推荐你

用户这次贴的第二段（录音手表那段）里，DeepSeek 推荐了声鸽、Recly、TicNote，并且明确写了
「TicNote 在 MCP 上没有明确信息」。这三个事实放在一起，就是一条可复用的规律：

| 机制 | 它要求你做什么 | 反面（会被 AI 写成负面结论） |
|---|---|---|
| **第三方页面背书** | 在目录站/评测站/商店页各留一个能互相对上的页面 | 只有自家官网一句话，AI 不敢引 |
| **可判定的硬事实** | 一句话里带数字和明确能力（"支持 MCP"、"24 小时连续录音"、"3–5 米拾音"） | 全是「强大、智能、极致」，AI 无法判定，只能不写 |
| **出现在清单型内容里** | 挤进 "best X for Y"、"alternatives to Z" 这类列表页 | 不在任何清单里，就永远不进候选池 |

**推论：** 目录站的价值不只是外链 —— **目录站就是 AI 的语料库**。
你每上一个目录，就多一个「AI 敢引用的独立页面」。这就是为什么这件事要一次铺开，而不是每周挤一个。

**写 listing 的硬规矩**（每条都要能单独被抄走）：

1. 一句定义句：`X 是一个给 <谁> 用的 <什么>，它 <做什么>，不需要 <什么>。`
2. 三个可验证数字（体积 / 耗时 / 价格 / 版本 / 条数）。
3. 一个明确的「不做什么」（比功能列表更能让 AI 区分你和竞品）。
4. 一条可点开的证据链接（仓库 / 文档 / App Store）。

## 2. 三条泳道，别混用

同一批平台，对不同产品的价值差 10 倍。作战台里点上面那三个 tab 就是在切这个。

| 泳道 | 主战场 | 次战场 | 别浪费时间 |
|---|---|---|---|
| **消费者 iOS App**（Blockwipe / 十点睡 / Dopamine Tax） | App Store 推荐提名、r/TestFlight、indie-apps.com、Indie App Catalog、r/iosapps | Product Hunt、Uneed、Peerlist、AlternativeTo | DevHunt、TAAFT、Glama、mcp.so、Hacker News（除非有技术故事） |
| **开发者工具 / 开源**（DSH 插件、U-King） | Show HN、Peerlist、DevHunt、Glama/mcp.so/Smithery（真 MCP 才上） | Product Hunt、Uneed、Fazier、V2EX、Indie Hackers | 所有 iOS 应用目录 |
| **AI 产品 / Agent / MCP** | Peerlist、Uneed、CodeHype、TAAFT、Future Tools、官方 MCP Registry | Product Hunt、Fazier、Toolify（付费） | 所有 iOS 应用目录 |

**判据只有一句：那家站的访客，会不会是这个产品的用户？** 不会 → 它只剩外链价值，排在最后。

## 3. 注册清单（先把账号办齐，再谈发布）

一次性办完，别到发布当天才发现要验证。

| 身份方式 | 平台 | 备注 |
|---|---|---|
| **GitHub 登录** | DevHunt、Glama、mcp.so、Smithery、官方 MCP Registry、V2EX（部分） | 用主 GitHub 账号，和仓库同源，审核更快 |
| **需要实名/身份验证** | **Peerlist** | 只收「已验证的个人资料」：真名 + 真人照片；工作证明免费，身份证验证一次性小额；**卡住就发不了** |
| **邮箱注册** | Product Hunt、Uneed、Fazier、TinyLaunch、Microlaunch（X/Google）、CodeHype、StartupBase、Launching Next、AlternativeTo、SaaSHub、TAAFT、Future Tools、indie-apps、Indie App Catalog、Discover Indie Apps、Launch Indie Apps、Indie App Santa、BetaList、Indie Hackers、Hacking with Swift | 统一用 catch-all 别名（如 `promo@<你的域名>`），别用 Gmail 主号，后面查信方便 |
| **要养号** | **Reddit**（r/iosapps 要 300+ karma 且 90 天；r/apple 要近一月 5 条非自推发言） | 现在就去养，别等到要发的时候 |
| **要开发者账号** | App Store Connect（推荐提名） | 已有 |

> 建议：**所有平台用同一个头像、同一个一句话简介、同一个官网 URL。**
> 「名字 + 一句话 + 分类」三处一致，是 AI 把你看成同一个实体的前提；不一致会被当成三个不同的东西。

## 6. 六个会让你白忙的坑

1. **提交 ≠ 排期。** Uneed 提交完只是存了草稿，必须回 dashboard 选「免费排队 / Fast-track / Skip」，不选永远不发。
2. **「免费」经常等于「挂 badge」。** Fazier / TinyLaunch / StartupBase / CodeHype 都要你站上挂回链；badge 掉了外链就没了。没有官网的产品，这几家等于不存在。
3. **Peerlist 的三个卡点**：实名验证、项目必须 100% 完成、周一 UTC 零点开榜。求票 = spam。
4. **r/iosapps 不是发布当天能发的**：要上架满 30 天 + 300 karma + 90 天账号。新品当天发必删。
5. **App Store 直链不够用的五家**：Fazier、TinyLaunch、StartupBase、BetaList、SaaSHub —— 都要官网。
6. **买票/批量新号投票**：Uneed 直接下架，Product Hunt 2026 算法专门惩罚求票。

## 8. 怎么用这套文件

```bash
cd 发布矩阵
# 给某个产品出一张作战台（默认站到产品自己的泳道）
node build-matrix.mjs platforms.json --product products/blockwipe.json
# 出一张通用版（三个泳道全开）
node build-matrix.mjs platforms.json --out dist/发布矩阵-通用版.html
```

产物是零依赖单文件 HTML：双击就能开，不需要服务器、不需要登录。
勾选的进度存在浏览器 localStorage（key 里带产品 slug，不同产品互不干扰）。

**别忘了它不做什么**：它只开页、递物料、记进度。**提交按钮永远你自己按。**

## 9. 第三个投递面：ClawMe（手机上只做「点一下去注册」）

发布台 / 目录页解决「在哪发、发什么」，**ClawMe 解决「人怎么被推着动那一下」**。
三个渠道分工清楚，别互相替代：

| 渠道 | 在哪 | 干什么 | 不适合 |
|---|---|---|---|
| 发布台（web） | 电脑浏览器 | 看全量、切泳道、勾进度、复制物料 | 碎片时间 |
| 目录页（Chrome） | 电脑浏览器 | **真正提交**（要传截图、写长文、填仓库 URL） | 出门在外 |
| **ClawMe** | iPhone | **只做「打开 → 注册 → 回来勾掉」**这一件事 | 任何要上传/长文的动作 |

所以 `platforms.json` 里每个平台带 `phone: true/false`：21 家要传截图/写长文/进 App Store Connect 的是
`phone:false`，剩下 14 家（PH / Peerlist / Uneed / indie-apps / Indie App Catalog / Crowdstax…）才投手机。

```bash
# 先看今天要发什么（不发）
node send-clawme.mjs platforms.json --product products/blockwipe.json --dry-run
# 真发：1 张简报 + 最多 3 张「打开链接」卡，发完记进度
node send-clawme.mjs platforms.json --product products/blockwipe.json --limit 3 --wait
# 重来一遍（清掉「已发」记录）
node send-clawme.mjs platforms.json --product products/blockwipe.json --reset
```

进度存 `~/.clawme-bomber/<产品 slug>.json`，同一家不会发第二次；`--lane dev` 换泳道，`--phase launch` 只发某一段。

**实测坑（2026-11-17，值得记住）**：
ClawMe 后端如果在带代理变量的终端里启动（`https_proxy=127.0.0.1:7897` + `NODE_USE_ENV_PROXY=1`），
APNs 会报 `The pending stream has been canceled` —— 卡片照样入队、手机 App 里能看到，**但锁屏推送不会响**。
同一台设备、同一份配置，改用 LaunchAgent（`net.clawme.bridge`，不继承 shell 环境）启动后
`delivery: {ok:true, sent:1, total:1}`。**判据永远是 `delivery.ok`，不是 HTTP 201。**

## 10. 反向工程：那条「发现了 Move to Top」的通知，和你该学的邮件营销

用户 2026-11-17 收到一条推送，说「偶然发现了 DeepSeek Harness 代码库的 Workspace Hub / Move to Top
功能……这种专注的工作区工作流程显得尤为及时」。**这不是巧合，是一台引擎干的事**：

```
扫 GitHub / npm / PH 新条目  →  判断「这东西值不值得写」  →  生成一段评价  →  发出去（邮件/推送/榜单）
```

它凭什么发现了 move-top？不是因为我们做了推广，而是因为**元数据写对了**：

| 它读的东西 | 我们当时写成了什么 |
|---|---|
| 仓库 description / topics | 一句话说清「把工作区一次性提到最上面」，不是「DSH 插件合集」 |
| npm 包名 + keywords | `dsh-plugin-workspace-move-top`，名字本身就是搜索词 |
| README 第一段 | 定义句 + 安装命令 + 一句「不做什么」 |
| 依赖声明 | `peerDependencies` 写清宿主版本 → 机器能判「这插件是给谁用的」 |

**这就是「被 AI/引擎发现」的真实机制：不是内容多，是字段齐。**

### 我们自己也该跑同一台引擎（这就是邮件营销的正确形态）

不是买名单群发，是**先发现值得联系的人，再写一封他愿意回的信**。四步：

1. **源**：Crowdstax 的 71 家平台目录（每条标了类型与审核日）、Product Hunt 日榜、GitHub trending、
   HN Show、App Store 新上架；我们自己的库里还有 `stringers` MCP 的 plays/products/apps。
2. **判据**（一句话，可执行）：这个人/这个站**最近 30 天有没有在做跟我同类的产品**？
   有 → 他可能需要我的东西；没有 → 不写信。
3. **信**（3 句，不超过 90 字）：① 我看到你在做 X；② 我们做了一个能解决 X 里某个具体麻烦的东西（一句定义）；
   ③ 有个能直接用的东西/链接，不用回复也行。**不提价格、不附附件、不放三个以上链接。**
4. **台账**：谁发了、哪天、回了没有、下次什么时候跟。`~/.clawme-bomber/` 旁边建 `outreach.json` 即可。

**红线**：一封一写（不群发模板）、每封留退订方式、同一人 30 天内不超过 2 封、不买名单。
Gmail 一天发几十封就会进垃圾箱，这件事的瓶颈是「写得好」，不是「发得多」。

**另一个用法（更省力）**：与其发信，不如**让自己出现在这类引擎的扫描面上** ——
GitHub topics、npm keywords、awesome 列表 PR、llms.txt、sitemap/RSS、以及第 2 节的目录站。
一条被收录的目录条目，等于常年在线的一张「AI 可引用卡」。
