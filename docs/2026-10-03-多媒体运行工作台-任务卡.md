# 任务卡：多媒体运行工作台 v0.1

日期：2026-10-03 · 参考物：WeSight 图文动态截图（三栏：文章树 / 文案+分享 / 图文卡工坊）
硬约束：**只用 Python + 网页**，零 npm、零 pip 依赖；豆包 / dsh / WorkBuddy / Claude Code 都能直接用。
算力：**只走虾盘云**（`https://api.u-claw.org.cn`），作图用 gpt-image-2 与 gpt-image-2.5 系列。

---

## 1. 一句话定义

把「一篇文章」在本机变成「6 张能发的图文卡 + 一份能发的发布台」，
中间所有作图都调虾盘云，全程只开一个本地网页，不装任何东西。

## 2. 定位决定（自用 vs 对外）

**自用优先，但按「别人拿到也能自己跑」的形态交付 —— 即：开源单机工具，不做 SaaS。**

- 做 SaaS 要额外背上：账号体系、支付对账、发票、内容审核、备案、客服、滥用风控。这些成本远大于工具本身，而现在的真实痛点（自己发内容）一个都用不上。
- 对外分发的边际成本≈0，靠三条免费渠道：① 开源仓 + README；② skill 包（豆包/dsh/Claude Code/WorkBuddy 装进 skills 目录）；③ 虾盘云官网挂「配套工具」。
- 别人自带虾盘云 key → 你零算力成本、零合规负担；想赚钱就赚在虾盘云算力上，而不是赚在这层壳上。
- **内容当然发到外面**（这才是目的）。发布动作保持 media-publish 已定的硬边界：只开提交页 + 递文案，不碰账号密码、不替你点「提交」。

## 3. 抄什么、不抄什么（读图结论）

| 截图里的东西 | 我们的做法 |
|---|---|
| 左栏：文章树 + 文件夹 + 字数（review 290 / excalidraw 10…） | 扫本地目录（默认 `mp-articles/`，可切任意路径），树 + 字数 + 修改时间 + 底部合计 |
| 中栏：正文编辑 + 右上「分享」 | Markdown 编辑 + 预览；「分享」弹窗做平台多选 |
| 弹窗：知乎 / CSDN / 掘金 / B站专栏 / 今日头条 / 微博头条文章 | 复用 `catalog.json`（现有 41 个平台），**补 `csdn`、`toutiao` 两个 id**；这 6 个作为默认勾选组 |
| 弹窗那句「正文与图片只通过 127.0.0.1 临时通道传输」 | 照抄这句话，并且**说到做到**：服务只绑 127.0.0.1，每次启动生成一次性 token |
| 右栏：WeSight 图文动态（① 文案 ② 图片 ③ 检查） | 右栏改成「图文卡工坊」，三步流程保留 |
| 风格模板：文字排版 / 实拍摄影 / 杂志拼贴 / 插画叙事 / 信息图解 / 截图增强 | 6 个风格 = 「排版模板 + 提示词前缀 + 默认模型 + 默认尺寸」四件套，数据驱动放 `styles/cards.json` |
| 二级样式：基础 / 漫画 / 插图 / 简约 / 涂鸦 / 便签 | 6 个二级皮肤，纯 CSS，只换字体/配色/装饰，不动结构 |
| 3:4 实时预览 | 预览框固定 3:4，改参数即时重渲染 |
| 内容设置：页数 6 张 / 来源（正文提取·AI 生成·手动）/ 图片文字 20/100 | 页数 3–9；来源三选一；图上文字单独一个输入框（**不让模型写中文长句**） |
| 「一键生成 6 张内容」 | 拆段 → 每段调虾盘云出底图 → 套排版模板 → Edge headless 截图成 1080×1440 PNG |
| 皮肤 | **不抄**。截图那套偏「AI 味」，按你口味走浅色卡片化 + 单色强调 |

## 4. 架构

```
media-publish/
  workbench/                      ← 新增（v0.1 全部在这里，不动现有引擎）
    server.py                     ← 单文件，Python 3.10+ 标准库，只绑 127.0.0.1
    ui/index.html                 ← 单文件前端：原生 JS + CSS，无框架、无 CDN
    styles/cards.json             ← 6 风格 × 6 皮肤的模板与提示词
    README.md                     ← 三条命令跑起来
  catalog.json                    ← 复用（补 csdn / toutiao）
  output/发布台-*.html            ← 复用现有产物格式
  mp-articles/<slug>/             ← 复用现有落盘结构
```

### 后端 HTTP 契约（`server.py`）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/articles` | 扫描文章根目录 → 目录树 + 每篇字数 + 修改时间 |
| GET | `/api/article?path=` | 读单篇正文（md/html） |
| GET | `/api/models` | 透传虾盘云 `GET /v1/models`，只留作图组 |
| POST | `/api/image` | 文生图 → `/v1/images/generations`，b64 落盘到 `images/` |
| POST | `/api/image/edit` | 图生图/改图 → `/v1/images/edits`（multipart） |
| POST | `/api/cards/plan` | 正文 → 拆段计划（N 段 + 每段标题/要点） |
| POST | `/api/cards/render` | 模板 + 底图 → HTML → Edge headless 截 1080×1440 PNG |
| POST | `/api/publish/build` | 生成 campaign JSON + 发布台 HTML |
| POST | `/api/publish/open` | 在默认浏览器逐个打开平台提交页 |

### 界面命名（右栏 4 个动作）

1. **风格推荐** — 按文章类型给一个建议风格 + 「采用推荐 / 重新分析」
2. **6 个风格卡** — 文字排版 / 实拍摄影 / 杂志拼贴 / 插画叙事 / 信息图解 / 截图增强
3. **二级样式** — 基础 / 漫画 / 插图 / 简约 / 涂鸦 / 便签
4. **一键生成 N 张** — 底部主按钮，出图前给一行成本提示

## 5. 关键设计决定

1. **算力只有一条路**：全走虾盘云。key 由服务端解析（`XIAPAN_API_KEY` > `~/.uking/device.json` 的 `key`），**永不进前端、不进日志、不进命令行参数**。
2. **零依赖**：Python 标准库（`http.server` / `urllib` / `json` / `base64` / `subprocess` / `webbrowser`）；前端原生 JS。判断能不能用只需一条：`python -V`。
3. **两种入口，一份逻辑**：
   - `python workbench/server.py serve` → 开网页给人用
   - `python workbench/server.py cli image --prompt ...` → agent 无人值守出图/出卡/出发布台
   - 这样豆包 / dsh / WorkBuddy / Claude Code 四种壳都只学会一条命令。
4. **作图走可试模型清单**（实时拉，不写死）：`gpt-image-2`、`gpt-image-2.5-1k`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`doubao-seedream-5-0-260128`、`seedream-4-5`、`qwen-image-2.0-pro`、`wan2.7-image-pro`。
5. **图上文字由排版层叠，不由模型写**：uking-aigc 已实锤扩散模型写不准中文长句/二维码。模型只出**底图/插图**，标题正文用 HTML 叠上去。
6. **不替你点提交**：`/api/publish/open` 只 `webbrowser.open` 提交页并复制文案，靠你浏览器里的登录态。

## 6. 分阶段与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0 骨架** | 起服务 + 三栏 + 文章树 + 模型下拉 | 浏览器打开 `127.0.0.1:8721`，看到**真**文章列表和**实时**模型清单 |
| **P1 出图** | 6 风格模板 + 模型可选 + 落盘 | 6 种风格各出 1 张，图进 `images/`，可单张重生成 |
| **P2 图文卡** | 拆段 → N 张 1080×1440 PNG | 一篇文章出 6 张，风格统一，单张可改可换 |
| **P3 发布** | 发布台 HTML + 6 平台开页 | 点一次开出 6 个提交页，标题/正文已复制到剪贴板 |
| **P4 记录** | 历史/进度落盘 | 关掉网页再打开，勾选状态和生成记录还在 |

建议节奏：**P0+P1 先跑通（这是「能出图」的最小闭环），看到效果再上 P2/P3。**

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 模型写不准中文长句 | 排版层叠字，模型只出底图；提示词里明确「no text」 |
| 出图烧钱（一篇 6 张） | 出图前显示「本次将生成 N 张」，二次确认可关；单张重生成而不是全部重来 |
| 平台提交页改版 | `catalog.json` 单点维护（已有约定） |
| 本地服务被别人访问 | 只绑 `127.0.0.1` + 启动随机 token，写进 README |
| 和 tokenfish 抢虾盘云额度 | 同一个钱包，出图前先查余额；余额不足给「去充值」按钮 |

1. **没余额也能走完策划全流程**：风格、歌词、制作卡全部照常产出并可反复改，只在最后提交前提示充值。
   用户是「看到完整成品预览、只差一步付款」，而不是「一进来就被要求充钱才能开始」。

   不重做策划、不丢上下文。这一点要写进客户端的 `next_action` 提示语。
3. **充值引导给足**：余额不足时明确「还差 ¥X」+ 一键复制 key + 打开充值页（`topup` 已有）。
